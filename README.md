# Vaelro Website

Marketing site for [vaelro.co](https://vaelro.co), a two-person AI automation
and web agency in Waupaca, WI.

React 19 · Vite · TypeScript · Tailwind CSS v4 · React Three Fiber · Framer
Motion · Lenis · React Router v7

## Development

```bash
npm install
npm run dev      # local dev server (renders in the browser, no prerender)
npm run build    # typecheck, build, and prerender every page into dist/
npm run preview  # serve the production build locally
```

## How pages are built

`npm run build` prerenders every route to static HTML, so search engines, AI
crawlers, and link previews get each page's full content and head tags in the
first response. React then hydrates that markup in the browser.

- [`src/entry-server.tsx`](src/entry-server.tsx) renders one route.
  [`scripts/prerender.mjs`](scripts/prerender.mjs) crawls internal links from
  `/` and writes `dist/<route>/index.html`, `dist/404.html`,
  `dist/sitemap.xml`, and `dist/_redirects`. Pages nothing links to are listed
  in `UNLINKED_ROUTES`.
- The build fails if a page renders nearly empty, has no `<h1>`, links to a
  page that 404s, or is missing (or duplicates) a head tag. It warns when a
  title or description is outside search-snippet length.
- Components must be able to render on the server: no `window`, `document`,
  or storage during render. For browser-only state use `useHydrated`,
  `useMediaQuery`, and `useNow` in [`src/hooks`](src/hooks). The dev server
  does not prerender, so check that kind of change with
  `npm run build && npm run preview`.

## SEO

- Every page renders `<Seo>` ([`src/seo/Seo.tsx`](src/seo/Seo.tsx)) with its
  own title, description, canonical path, and JSON-LD from
  [`src/seo/schema.ts`](src/seo/schema.ts).
- The business name, address, email, phone, and social profiles live in
  [`src/data/business.ts`](src/data/business.ts). The footer, the Contact page,
  and the structured data all read from it, so they always match. Adding a
  phone number there puts it in all three.
- `public/robots.txt` and `public/llms.txt` are plain files; the sitemap is
  generated by the build.

## Editing content

- **Portfolio projects and client testimonials**:
  [`src/data/projects.ts`](src/data/projects.ts).
- **Contact page FAQ**: [`src/data/faqs.ts`](src/data/faqs.ts). It is also
  published as the page's FAQPage structured data.
- **Service pages**: [`src/pages/WebDesignPage.tsx`](src/pages/WebDesignPage.tsx)
  and [`src/pages/AutomationPage.tsx`](src/pages/AutomationPage.tsx).
- **Workshop series**: [`src/data/workshop.ts`](src/data/workshop.ts).
- **Booking URL**: [`src/lib/booking.ts`](src/lib/booking.ts).
- **Contact flow**: the multi-step lead form lives in
  [`src/components/sections/ContactFlow.tsx`](src/components/sections/ContactFlow.tsx).
  It POSTs to a Google Apps Script Web App (source of truth:
  [`backend/apps-script/Code.gs`](backend/apps-script/Code.gs)) which appends a
  row to the "Vaelro Website Leads" Sheet and emails hello@vaelro.co. Spam is
  blocked by a honeypot field.

## Deploy (Netlify)

Connect the GitHub repo in Netlify. `netlify.toml` sets the build command
(`npm run build`) and publish directory (`dist`). The build writes
`dist/_redirects`, which serves each prerendered page at its slash-free URL;
any other path gets the prerendered `404.html` with a real 404 status. The
contact flow submits directly to Apps Script, so no Netlify Forms
configuration is required.

Custom domain: add `vaelro.co` in Netlify Domain settings, then point DNS at
Wix (CNAME `www` → the Netlify site, A records per Netlify's instructions).
SSL is auto-provisioned.
